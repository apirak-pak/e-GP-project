# โครงสร้างและการทำงานของโปรเจ็ค

เอกสารนี้สำหรับคนที่จะรับงานพัฒนาต่อ เริ่มใช้งานตาม [README](../README.md) และดูข้อจำกัดของแหล่งข้อมูลใน [DATA_SOURCES](DATA_SOURCES.md)

## โครงสร้างไฟล์

```text

│  ├─ provinces.json     รายชื่อ 77 จังหวัดสำหรับตัวกรอง
│  └─ web/               HTML, JavaScript, CSS ของ dashboard
├─ docs/                 เอกสารแหล่งข้อมูลและโครงสร้างระบบ
├─ examples/             CSV ตัวอย่างและแม่แบบนำเข้า
├─ scripts/              สคริปต์ทดสอบ API แบบไม่แสดงคีย์

├─ .env                  คีย์ API ในเครื่องเท่านั้น (ไม่ส่งขึ้น Git)
├─ .env.example          รูปแบบไฟล์คีย์สำหรับผู้เริ่มใช้งาน
├─ run.ps1               เปิดเว็บในเครื่อง

├─ test.ps1              ตรวจการแปลงข้อมูลโดยไม่ใช้ API
```

## เส้นทางข้อมูล

1. `sync_egp.ps1` เรียก `app.sync_egp` และส่งปีงบประมาณ คำค้น ช่วงวงเงิน และจำนวนรายการ
2. `app.sync_egp` อ่าน `DGA_API_KEY` จาก `.env` แล้วเรียก EGP-CONTRACT หนึ่งครั้งต่อการรันหนึ่งรอบ คีย์ไม่ถูกเขียนลงโค้ด ฐานข้อมูล หรือบันทึกคำขอ
3. API ส่ง JSON กลับมา โปรแกรมตรวจ `success` และ `data` แล้วแปลงชื่อฟิลด์ วันที่ไทย และสถานะให้ตรงกับรูปแบบภายใน `app.location` ระบุจังหวัดของงานจากชื่อประกาศเมื่อมีคำว่า `จังหวัด` หรือ `จ.` ชัดเจน แยกจากจังหวัดหน่วยจัดซื้อที่ API ส่งมา หากโครงการมีผู้ชนะหลายราย จะไม่ใช้ยอดรวมของโครงการนั้นคำนวณสัดส่วนให้บริษัทใดบริษัทหนึ่ง
4. โปรแกรมตรวจข้อมูลจำเป็นก่อนบันทึกใน `data/egp.db` โดยใช้ `project_id` เป็นรหัสหลัก การดึงรหัสเดิมซ้ำจะอัปเดตแถวเดิม
5. `app.server` อ่าน SQLite เพื่อส่ง `/api/dashboard` ให้ `app/web/app.js` ตัวกรองบนเว็บใช้ฐานข้อมูลในเครื่อง จึงไม่เรียก DGA อีก ตารางเลือกหน้าได้ หน้าละ 50 รายการ แต่ตัวเลขสรุปและสัดส่วนคำนวณจากทุกรายการที่ตรงตัวกรอง
6. เมื่อคลิกชื่อผู้ชนะ หน้าเว็บเรียก `/api/winner-projects` ด้วยตัวกรองชุดที่แสดงอยู่และชื่อผู้ชนะเดียวกัน API นี้ส่งโครงการครั้งละ 50 งาน พร้อมจำนวนงาน ยอดรวมราคาที่ชนะ และจำนวนงานที่มีราคา โดยไม่เอาวงเงินงบประมาณไปแทนราคาที่ชนะ

บันทึก `data/api_requests.jsonl` เก็บเวลาที่สคริปต์พยายามเรียก API และชื่อบริการ ไม่มีคีย์ บันทึก `api_sync_runs` ใน SQLite เก็บจำนวนรายการของการดึงที่สำเร็จ ตัวนับในเครื่องไม่ใช่ยอดโควตายืนยันจาก DGA

## ขอบเขตข้อมูลและกฎธุรกิจ

- `EGP-CONTRACT` เน้นโครงการที่เข้าสู่ขั้นทำสัญญาแล้ว ยังไม่ครอบคลุมประกาศใหม่และงานระหว่างประมูล
- `budget` คือวงเงินงบประมาณ, `reference_price` คือราคากลาง, `winning_price` คือยอดตกลงจ้างของโครงการที่ผูกกับผู้ชนะรายเดียวได้
- สถานะ `ทำสัญญาแล้ว` มาจากการพบข้อมูล `contract` ในผล API แม้ข้อความสถานะดิบจะเป็น “ระหว่างดำเนินการ”
- สัดส่วนผู้ชนะคิดจากจำนวนโครงการที่ระบุชื่อผู้ชนะและมีสถานะประกาศผู้ชนะหรือทำสัญญาแล้วภายใน **จังหวัดหน่วยจัดซื้อ** ที่เลือกได้หลายจังหวัดและตัวกรองอื่น ๆ แต่ละโครงการนับหนึ่งงาน ไม่มีการอ้างว่าเป็นส่วนแบ่งตลาดทั้งหมดหรือสัดส่วนของพื้นที่ก่อสร้างจริง
- คำค้น `จ้างก่อสร้าง` เป็นการกรองเบื้องต้น ต้องตรวจนิยามประเภทงานกับบริษัทก่อนใช้เป็นรายงานทางธุรกิจ
- รายชื่อจังหวัด 77 แห่งมาจาก [ข้อมูลอ้างอิงจังหวัดของ govspending](https://api-govspending.data.go.th/api/get/ref/provinces) โดยตัดพัทยาซึ่งไม่ใช่จังหวัดออก หากชื่อประกาศไม่บอกพื้นที่ชัดเจน โปรแกรมจะใช้ `ไม่ระบุพื้นที่โครงการ` แทนการเดา
- ตัวกรองจังหวัด รายชื่อโครงการผู้ชนะ จำนวนจังหวัด และจำนวนโครงการต่อจังหวัดใช้คอลัมน์ `projects.agency_province` ซึ่งหมายถึงจังหวัดของหน่วยงานจัดซื้อ; `projects.province` คือพื้นที่งานที่อ่านจากชื่อประกาศ และแสดงแยกพร้อมหมายเหตุเมื่อแตกต่างหรือยังระบุไม่ได้
- ยังไม่มี AI ในขั้นดึงหรือแปลงข้อมูล และไม่มีการเรียก AI จากหน้าเว็บ

## จุดเริ่มต้นสำหรับผู้พัฒนาต่อ

รัน `./test.ps1` จากโฟลเดอร์รากเพื่อตรวจการแปลงข้อมูลแบบไม่ใช้คีย์หรืออินเทอร์เน็ต รัน `python -m app.sync_egp --help` เพื่อดูตัวเลือกของตัวดึงข้อมูล ถ้าจะเพิ่มแหล่ง API ใหม่ ให้แยกตัวดึง/ตัวแปลงของแหล่งนั้น แล้วเก็บที่มาของแต่ละระเบียนใน `source_kind` และ `source_name`

ก่อนเปิดให้ผู้อื่นใช้ผ่านเครือข่าย ต้องเพิ่มการยืนยันตัวตน สิทธิผู้ใช้ HTTPS และการสำรองฐานข้อมูล เว็บเซิร์ฟเวอร์ปัจจุบันผูกกับ `127.0.0.1` เท่านั้น
