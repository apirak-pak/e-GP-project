# แหล่งข้อมูลสำหรับพัฒนาระบบ

ข้อมูลที่โปรแกรมต้องใช้มีอย่างน้อยสองลักษณะ ซึ่งอาจมาจากคนละชุดข้อมูล:

1. **ข้อมูลย้อนหลังและผู้ชนะ** สำหรับดูสถิติและสัดส่วนผู้ชนะ
2. **ประกาศปัจจุบัน** สำหรับติดตามงานใหม่และสถานะระหว่างประมูล

## จุดเริ่มต้นที่ตรวจพบ

- [data.go.th: ข้อมูลโครงการจัดซื้อจัดจ้างปีงบประมาณ 2568](https://data.go.th/th/dataset/egp-contact-2568) มีทรัพยากร CSV และระบุว่าเป็นชุดข้อมูลที่ไม่ปรับปรุงหลังจัดเก็บ เหมาะกับการศึกษาข้อมูลย้อนหลัง ไม่ควรถือเป็นข้อมูลประกาศล่าสุด
- [คู่มือ API ของ Thailand Government Spending](https://govspending.data.go.th/doc-api) ระบุบริการ `EGP-CONTRACT` แบบ GET มีจังหวัด วงเงิน สถานะ และข้อมูลสัญญา/ผู้ชนะ ส่วน [หน้าชุดรายชื่อผู้ชนะ](https://data.go.th/th/dataset/egpwinner) มีไฟล์ CSV ที่มีเพียงชื่อและเลขนิติบุคคล ไม่พอสำหรับ dashboard ตามจังหวัดและราคา
- [หน้าลงทะเบียน API ของ data.go.th](https://opend.data.go.th/register_api/signup.php) ระบุว่ารับ Key ฟรี และแสดงขีดจำกัด 1,000 ครั้งต่อวันต่อผู้ใช้งาน ณ วันที่ตรวจ 5 ตุลาคม 2569

## ผู้ใช้โปรเจ็คต้องทำอะไร

สำหรับการทดลองหน้าจอและงานหลังบ้านในเครื่อง **ยังไม่ต้องสมัครบัญชีใด** โปรแกรมใช้ข้อมูลตัวอย่างหรือ CSV ที่นำเข้าเองได้

เมื่อจะเชื่อมข้อมูลจริงผ่าน API ให้บริษัทกำหนดผู้รับผิดชอบบัญชีและอีเมลที่บริษัทดูแล จากนั้นสมัครที่ data.go.th เพื่อรับ Key การสมัครนี้แยกจากการสมัครเป็นผู้ค้าหรือเจ้าหน้าที่ในระบบ e-GP อย่าส่ง Key หรือรหัสผ่านในแชต และอย่าเก็บใน Git หรือไฟล์โค้ด สำหรับ local development ให้เก็บใน `.env` ซึ่งอยู่ใน `.gitignore`

## หลังสมัครและยืนยันอีเมล

1. เข้า [หน้าผู้พัฒนา data.go.th](https://opend.data.go.th/register_api/) แล้วล็อกอิน
2. ดู API Key ในหน้า Profile ตาม [คู่มือ DGA](https://data.go.th/uploads/page_images/2025-07-08-051605.3384232025-03-07-DATAGOTH3USERMANUAL.pdf)
3. เปิดหน้าชุดข้อมูลที่ต้องการ แล้วดูปุ่ม **Data API** หรือคู่มือเฉพาะบริการเพื่อคัดลอก URL, วิธี GET/POST และพารามิเตอร์
4. คัดลอก `.env.example` เป็น `.env` แล้วเปิด `.env` เพื่อแทน `PASTE_YOUR_KEY_HERE` ด้วย Key จริงในบรรทัด `DGA_API_KEY=` อย่าใส่เครื่องหมายอัญประกาศหรือเว้นวรรคเพิ่ม และอย่าส่งไฟล์ `.env` ให้ใคร
5. จากโฟลเดอร์รากของโปรเจ็ค ทดลองบริการโครงการจริงด้วย `./scripts/test_egp_api.ps1 -Year 2568 -Limit 1` แล้วดึงข้อมูลลงฐานข้อมูลด้วย `./sync_egp.ps1 -Year 2568 -Limit 20` สคริปต์อ่าน Key จาก `.env` และไม่แสดง Key หรือ URL คำขอ

คู่มือบริการปัจจุบันของ govspending ระบุ `EGP-CONTRACT` เป็น GET และต้องส่ง `api-key` เป็นพารามิเตอร์ของคำขอ สคริปต์จึงประกอบ URL ในหน่วยความจำเท่านั้น ไม่พิมพ์ URL หรือ Key ลงหน้าจอ และไม่เก็บไว้ในฐานข้อมูล วิธีนี้เป็นไปตามรูปแบบที่ผู้ให้บริการกำหนด แต่ URL อาจปรากฏใน log ฝั่งผู้ให้บริการ จึงควรใช้คีย์บัญชีบริษัทเมื่อส่งมอบงาน ส่วน `scripts/test_dga_api.ps1` เป็นเครื่องมือทั่วไปสำหรับทดสอบ API แบบ header ซึ่งใช้กับบริการนี้ไม่ได้

ตัวอย่างการทดสอบถึง 7 ตุลาคม 2569: บริการ `EGP-CONTRACT` ตอบกลับสำเร็จด้วยคีย์ใน `.env` และนำเข้าผลค้นหา 15 หน้าแรกของปีงบประมาณ 2568 คำค้น `จ้างก่อสร้าง` ได้ 14,972 รายการจากที่ API ส่งมา 15,000 รายการ (ข้าม 28 รายการที่ข้อมูลจำเป็นไม่ครบ) API รายงานผลค้นหา 106,246 รายการสำหรับเงื่อนไขนี้ ตัวเลข 14,972 เป็นภาพ ณ เวลาทดสอบ; ให้ดูยอดปัจจุบันบน Dashboard ข้อมูลที่นำเข้ายังเป็นเพียงบางส่วนของผลค้นหา ไม่ใช่ภาพตลาดครบทุกโครงการ

วันที่ 14 ตุลาคม 2569 ทดลองส่งคำขอเดียวสำหรับปีงบประมาณ 2568 คำค้น `จ้างก่อสร้าง` ที่ `offset=0` และ `limit=200000` หลังยกเลิกเพดาน 1,000 รายการที่โค้ดตั้งไว้ ผู้ให้บริการตอบ HTTP 504 (Gateway Timeout) โดยไม่ส่งข้อมูลที่นำเข้าได้ ฐานข้อมูลจึงยังมี 14,972 รายการและไม่มีบันทึกรอบนำเข้าสำเร็จเพิ่ม การยกเลิกเพดานในโค้ดไม่ได้ยกเลิกข้อจำกัดหรือโควตาของผู้ให้บริการ การขอข้อมูลทั้งหมดในคำขอเดียวจึงยังทำไม่สำเร็จ

วันเดียวกัน ทดลองอีกหนึ่งคำขอด้วย `limit=100000` และเงื่อนไขเดิม ผู้ให้บริการตอบ HTTP 504 อีกครั้ง ไม่มีข้อมูลนำเข้า จำนวนโครงการยังเป็น 14,972 รายการ ผลนี้บอกได้ว่าคำขอขนาดดังกล่าวไม่สำเร็จในเวลาที่บริการรองรับ แต่ยังสรุปเพดานสูงสุดต่อคำขอของ API ไม่ได้

จากนั้นทดลองลดขนาดคำขอ **10 ครั้งพอดี** โดยใช้ `year=2568`, `keyword=จ้างก่อสร้าง`, `offset=0` เหมือนกันทุกครั้ง:

| รอบ | `limit` | ผล |
| --- | ---: | --- |
| 1 | 50,000 | HTTP 504 |
| 2 | 25,000 | HTTP 504 |
| 3 | 12,500 | HTTP 200, ได้ครบ 12,500 รายการ |
| 4 | 18,750 | HTTP 504 |
| 5 | 15,625 | HTTP 500 |
| 6 | 14,062 | HTTP 200, ได้ครบ 14,062 รายการ |
| 7 | 14,843 | HTTP 500 |
| 8 | 14,500 | HTTP 500 |
| 9 | 14,250 | HTTP 500 |
| 10 | 14,000 | HTTP 200, ได้ครบ 14,000 รายการ |

ขนาดสูงสุดที่ **ทดลองแล้วสำเร็จ** คือ 14,062 รายการ ส่วนขนาดต่ำสุดที่ **ทดลองแล้วไม่สำเร็จ** คือ 14,250 รายการ ผล 500/504 ไม่ใช่คำประกาศเพดานทางการจากผู้ให้บริการ และอาจเปลี่ยนตามภาระงานหรือข้อมูลในหน้าที่ขอ การใช้งานประจำควรเผื่อระยะจากช่วงนี้ คำขอที่สำเร็จทั้งสามครั้งเป็นข้อมูลช่วงต้นที่มีอยู่ในฐานข้อมูลแล้ว จึงไม่เพิ่มจำนวนโครงการสุทธิ; ฐานข้อมูลยังมี 14,972 รายการ

ต่อมาในวันที่ 14 ตุลาคม 2569 ดึงหน้าถัดไปด้วย `year=2568`, `keyword=จ้างก่อสร้าง`, `offset=15000`, `limit=5000` สำเร็จในหนึ่งคำขอ API ส่ง 5,000 รายการ (JSON 10,147,788 ไบต์), บันทึกได้ 4,988 รายการ และข้าม 12 รายการที่ข้อมูลจำเป็นไม่ครบ จำนวนโครงการในฐานข้อมูลเพิ่มเป็น **19,960 รายการ** จากผลค้นหาที่ API รายงานรวม 106,246 รายการ จึงยังเป็นข้อมูลบางส่วน

คำขอถัดไป `offset=20000`, `limit=14000` ได้ HTTP 500 จึงแบ่งช่วงเดียวกันเป็นสองคำขอ: `offset=20000`, `limit=7000` และ `offset=27000`, `limit=7000` ทั้งคู่สำเร็จ API ส่งกลับรวม 14,000 รายการ บันทึกใหม่รวม 13,978 รายการ และข้าม 22 รายการที่ข้อมูลจำเป็นไม่ครบ จำนวนโครงการในฐานข้อมูลเป็น **33,938 รายการ** (ภาพ ณ วันที่ 14 ตุลาคม 2569) โดยใช้ 3 คำขอสำหรับงานรอบนี้ รวมคำขอแรกที่ล้มเหลว

ดึงเพิ่มอีก 20,000 รายการในสามคำขอที่สำเร็จ: `offset=34000`, `limit=7000`; `offset=41000`, `limit=7000`; และ `offset=48000`, `limit=6000` บันทึกใหม่รวม 19,982 รายการ ข้าม 18 รายการที่ข้อมูลจำเป็นไม่ครบ ฐานข้อมูลและ dashboard มี **53,920 โครงการ** (ภาพ ณ วันที่ 14 ตุลาคม 2569)

รอบล่าสุดดึงต่อสำหรับปีงบประมาณ 2568 และคำค้น `จ้างก่อสร้าง` ตั้งแต่ `offset=54000` ถึง `offset=86499` คำขอ `offset=69000, limit=5000` ตอบ HTTP 500 จึงแบ่งช่วงนั้นเป็นหน้าละ 2,500 รายการ ช่วงที่สำเร็จถูกบันทึกลง Supabase และคัดลอกกลับ SQLite แล้ว ทั้งสองฐานมี **86,204 โครงการ** และประวัติการดึงสำเร็จ **36 รอบ** ณ วันที่ 19 ตุลาคม 2569 ผู้ใช้สั่งพักการดึงข้อมูลไว้ หากจะดำเนินต่อ ช่วงถัดไปคือ `offset=86500, limit=2500`; จำนวนโครงการสุทธิอาจเพิ่มไม่เท่าจำนวนที่ API ส่งมา เพราะมีรหัสซ้ำหรือรายการที่ข้อมูลไม่ครบ

ช่อง `province` ที่ API ส่งมาอาจเป็นจังหวัดของหน่วยจัดซื้อ เช่น งานในเชียงใหม่แต่หน่วยจัดซื้ออยู่กรุงเทพมหานคร โปรแกรมจึงเก็บค่านี้เป็น **จังหวัดหน่วยจัดซื้อ** และใช้ช่องนี้สำหรับตัวกรองจังหวัด จำนวนโครงการต่อจังหวัด และสัดส่วนผู้ชนะ ไม่ควรตีความผลลัพธ์ว่าเป็นงานที่ก่อสร้างในจังหวัดนั้น โปรแกรมระบุ **พื้นที่โครงการ** จากชื่อประกาศเฉพาะเมื่อมี `จังหวัด...` หรือ `จ....` ชัดเจน และแสดงแยกในรายการกับรายละเอียด หากระบุพื้นที่งานไม่ได้ก็ยังค้นได้ตามจังหวัดหน่วยจัดซื้อ รายชื่อจังหวัดอ้างอิงจาก [บริการข้อมูลอ้างอิงจังหวัดของ govspending](https://api-govspending.data.go.th/api/get/ref/provinces) โดยไม่นับพัทยาเป็นจังหวัด

สคริปต์รายงานผลตอบกลับที่ตรวจได้ ได้แก่รหัส HTTP, ค่า `success`, จำนวนรายการในหน้านั้น และจำนวนผลค้นหาที่ API รายงาน หาก API ส่งตัวเลขโควตาใน header มาตรฐานที่ตรวจ สคริปต์จะแสดงด้วย ในการทดสอบรอบล่าสุดไม่พบตัวเลขโควตาคงเหลือ จึงยังใช้ตัวนับคำขอในเครื่องแทนยอดทางการไม่ได้

API ส่งคำตอบเป็น JSON ไม่ใช่ไฟล์ที่บันทึกไว้โดยตรง สคริปต์วัดขนาดคำตอบก่อนแปลงข้อมูล ตัวอย่างหน้าที่มี 1,000 รายการ (offset 4,000) มีขนาด 1,951,987 ไบต์ หรือ 1.95 MB ขนาดหน้าถัดไปอาจต่างกัน และฐานข้อมูล SQLite บนเครื่องมีขนาดไม่เท่ากับ JSON ที่รับมา

ก่อนใช้รายงานเชิงธุรกิจ ต้องตรวจนิยามงานก่อสร้างและคุณภาพข้อมูลเพิ่มเติม รวมถึงดึงข้อมูลครบตามขอบเขตที่บริษัทกำหนด
